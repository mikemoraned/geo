See [announcement](/posts/2026-11-21/) for context, but TLDR: this is a catch-up devblog-style post on where I am with Lookout, which is currently at `V1 alpha1`. Today we'll focus on getting real GPS samples from a train.

<!-- more -->

I go to Germany every year, and had been planning to visit a few places in the area around Mannheim, so this was a good opportunity to get a sense of what real experience on a train would look like. So, [one of the very first things](https://github.com/mikemoraned/geo/blob/main/apps/lookout/docs/completed-slices.md#mike-is-on-a-train-getting-data) I did was starting to record real GPS traces from my phone; this was done via a website on iPad/iPhone -> online redis -> dump in landing -> save for later analysis in bronze. The data from my phone wasn't too surprising: I know from using GPS in other Apps that it can vary a lot in accuracy.





I'd already [been playing around](https://github.com/mikemoraned/blescan/tree/m5/m5) with [M5 devices](https://m5stack.com), and so had one to develop on. So, as a way to keep this real, I adopted a requirement that anything I build must be able to run on an M5 device with an attached GPS sensor, as well as on a website. The App should be able do "opportunistic enrichment" where extra capacity is available but the core features should always work on an M5 device where the only connectivity it has is passive GPS.

It is totally ok, however, to do a bunch of processing up-front offline ahead of time. This is where I adopted the "Medallion Pattern", instantiated here roughly as:
* landing: device recordings, and other raw data, typically in a non-parquet native format, focussed on being easy to capture but not persisted
* -> bronze: similar data as landing, but in parquet format and persisted + also snapshots of external datasets
* -> silver: normalised and processed derived data, based on what's in bronze
* -> gold: distilled and minimised versions of silver data, targeted for deployment on the devices themselves

Getting things working on the M5 was a bit more complicated. This was actually where using Claude was super-useful as I am *far* less of an expert in ESP device stuff than what I've mentioned so far.

Btw, as an aside, for the rest of this devblog, I will refer to Claude in a similar way i.e. when it made a significant difference, I'll mention it. I used Claude for the vast majority of the work here, but I've made a point of not committing anything I don't personally understand or haven't driven very deliberately. I also know that I wouldn't have gotten anywhere near as far without using it, but that's more of a credit to the many billions of line of code that went into Claude's training. So, I don't wanna hide that I've used it extensively, but I also don't wanna start treating this as a "we did this" project; "I" did this on top of the shoulders of many *people*.
