# Rust 1.100 and the lookout workspace

*Assessment of 2026-11-19, made as `apps/lookout` moved from Rust 1.99.1 to 1.100.0 in 6a8e701c.
It draws on the [1.100.0 release notes](https://doc.rust-lang.org/1.100.0/releases.html), the Cargo
and Clippy documentation of that release, and a search of the workspace. A finding marked
"(checked)" rests on a small program compiled for this assessment. What the slice adopts moves into
the code and `.claude/rules/rust.md`, and the rest goes stale.*

This doc lists the changes in Rust 1.100 that bear on the lookout workspace, and where each one
applies. It is for whoever folds the release into the current slice's plan, or applies its library
additions to existing code. Line numbers hold at 6a8e701c.

The findings hold for rustc, Cargo, and Clippy 1.100.0, and for the `esp-1.98.1.0` toolchain.

## Toolchains

`apps/lookout` pins 1.100.0. The firmware for the M5 device, `crates/platform/m5/m5plus`, is a
workspace of its own and pins `esp-1.98.1.0`. Its build, the device build here, compiles four lookout
crates as path dependencies: `domain`, `predictor`, `platform-core`, and `m5-core`. This doc calls
them the shared crates. `tools/overture-mirror` pins 1.99.1, and the repo's other Rust projects pin
older releases.

`esp-1.98.1.0` rejects each 1.100 addition this doc names: `!` as a type, `str::trim_prefix`,
`Vec::from_fn`, and `bool::toggle` (checked). A 1.100 addition in a shared crate therefore breaks the
device build until `m5plus` moves to `esp-1.100.0.0`. This doc calls that move the esp upgrade.

A `rust-version` of `"1.98"` in each shared crate's manifest keeps library additions out of them.
Clippy's [`incompatible_msrv`](https://rust-lang.github.io/rust-clippy/rust-1.100.0/index.html#incompatible_msrv)
lint, part of `clippy::all`, then flags any standard library item stabilised after 1.98 in those
crates (checked). It misses language features: a shared crate can name `!` without a warning. The
`rust-version` rises with the esp upgrade.

## The never type

1.100 stabilises `!` as a type, and makes
[`Infallible`](https://doc.rust-lang.org/1.100.0/std/convert/type.Infallible.html) an alias of it.
The slice plans `TryFrom` impls with `type Error = !` for three conversions: `Uuid` to `GersId`,
`Uuid` to `PolylineId`, and `DateTime<Utc>` to `ExtractId`.

Clippy's [`infallible_try_from`](https://rust-lang.github.io/rust-clippy/rust-1.100.0/index.html#infallible_try_from)
lint flags a `TryFrom` impl whose error type is `Infallible` or `!`, and suggests `From`. It is part
of `clippy::all`, which the workspace sets to `warn`. Each planned impl therefore adds a warning to
`just clippy` (checked).

A `From` impl carries the same guarantee. Each `From<T>` impl brings a blanket `TryFrom<T>` whose
error type is `Infallible`, which 1.100 makes `!`. Given a `From` impl,
`let Ok(id) = GersId::try_from(uuid);` compiles (checked), and `GersId::from(uuid)` needs no pattern.

Three more facts bear on the choice:

- `domain` already implements two such conversions with `From`: `From<Uuid> for DeviceId` and
  `From<Uuid> for SessionId`.
- A `From` impl compiles on every toolchain in use, `esp-1.98.1.0` included.
- `PolylineId::of` and `ExtractId::at` return `Self`, so their signatures already state that the call
  cannot fail. Of the three conversions, only `Uuid` to `GersId` changes a call site:
  `GersId::new(Uuid::nil().to_string()).expect(…)` in `MotisSourceRowV4::example`.

No other code in the workspace names `Infallible`, and no trait or generic in it takes an error type.
The never type has no further use here.

## Cargo's lints

Cargo 1.100 adds [lints of its own](https://doc.rust-lang.org/1.100.0/cargo/reference/lints.html),
set under `[lints.cargo]`, or `[workspace.lints.cargo]` for a workspace. Three bear on this
workspace, and each warns by default. `just clippy` prints all three (checked).

- [`unused_workspace_dependencies`](https://doc.rust-lang.org/1.100.0/cargo/reference/lints.html#unused_workspace_dependencies)
  flags a `[workspace.dependencies]` entry that no member inherits. The level `allow` for it under
  `[workspace.lints.cargo]` silences it (checked).
- [`unused_dependencies`](https://doc.rust-lang.org/1.100.0/cargo/reference/lints.html#unused_dependencies)
  flags an unused entry in a member's `[dependencies]` or `[build-dependencies]`. It checks only the
  members a build selects, which for `just clippy` is every member, and it skips
  `[dev-dependencies]`.
- [`missing_lints_inheritance`](https://doc.rust-lang.org/1.100.0/cargo/reference/lints.html#missing_lints_inheritance)
  flags a member with no `[lints]` table while the workspace defines `[workspace.lints]`. Every
  member inherits the workspace lints, so it flags none.

At e20c4e57, `unused_workspace_dependencies` and `unused_dependencies` flagged four entries between
them: `m5-core`, `map`, and `wkt` in `[workspace.dependencies]`, and `transport` in `recorder`'s
`[dependencies]`. 6a8e701c removes all four.

## Library additions

### `str::trim_prefix` and `str::trim_suffix`

[`str::trim_prefix`](https://doc.rust-lang.org/1.100.0/std/primitive.str.html#method.trim_prefix)
removes a prefix that is present, and returns any other string unchanged. It replaces
`s.strip_prefix(p).unwrap_or(s)`. One site matches, at `crates/predictor/src/sentence.rs:47`, which
becomes `self.as_str().trim_prefix('$')`. `predictor` is a shared crate, so the change waits for the
esp upgrade.

`str::trim_suffix` has no site. `crates/motis/src/client.rs:73` keeps `trim_end_matches('/')`: it
strips every trailing slash, and `trim_suffix` strips one.

### `Path::trim_prefix`

[`Path::trim_prefix`](https://doc.rust-lang.org/1.100.0/std/path/struct.Path.html#method.trim_prefix)
does the same for a path. It replaces `strip_prefix(base)` followed by an `unwrap` or `expect`. Two
test helpers do that after stripping a temporary root: `crates/medallion/src/path.rs:523` and
`crates/recorder/tests/sessionise.rs:120`. With `trim_prefix`, a path outside the root fails the
test's comparison rather than panicking.

### `Vec::from_fn`

[`Vec::from_fn(n, f)`](https://doc.rust-lang.org/1.100.0/std/vec/struct.Vec.html#method.from_fn)
builds a `Vec` of `n` elements, calling `f` with each index. It replaces `(0..n).map(f).collect()`
where the index is a `usize` and the result a `Vec`. The gain is readability alone: collecting a
mapped range already allocates once.

One library site and ten test sites match:

- `crates/crossings/src/pointset.rs:98`, in `unpack`.
- `crates/crossings/tests/pack.rs:202`.
- `crates/evaluation/src/cone.rs:325`.
- `crates/evaluation/src/fixtures.rs:59`.
- `crates/evaluation/src/pick.rs`, at lines 146, 202, 220, and 340.
- `crates/evaluation/src/summarise.rs:427`.
- `crates/session_crossings/tests/derive.rs`, at lines 84 and 367.

A range over `u32` or `i64`, or one collected into a map, keeps its form.

## Dependency cooldown

Cargo 1.100 can ignore releases younger than a set age, a
[publish age](https://doc.rust-lang.org/1.100.0/cargo/reference/resolver.html#publish-age). The
[`registry.global-min-publish-age`](https://doc.rust-lang.org/1.100.0/cargo/reference/config.html#registryglobal-min-publish-age)
key holds the age. A seven-day age for the workspace takes two lines in
`apps/lookout/.cargo/config.toml`:

```toml
[registry]
global-min-publish-age = "7 days"
```

The resolver then skips a younger release unless `Cargo.lock` already holds it. Three limits apply
here:

- With the age set, `just audit-update` skips a fix younger than the age.
  [`CARGO_RESOLVER_INCOMPATIBLE_PUBLISH_AGE=allow`](https://doc.rust-lang.org/1.100.0/cargo/reference/config.html#resolverincompatible-publish-age)
  on its `cargo update` lifts the cooldown for that run.
- `cargo install` reads only user-level configuration, so the installs in the `prerequisites` recipe
  fall outside the cooldown.
- The device build runs the Cargo of `esp-1.98.1.0`, which predates the key.

## `cargo install` and lockfiles

[`cargo install`](https://doc.rust-lang.org/1.100.0/cargo/commands/cargo-install.html#dealing-with-the-lockfile)
uses the lockfile packaged with a crate by default, and `--locked` no longer changes resolution. The
six `--locked` options in the `prerequisites` recipe of `apps/lookout/Justfile` have no effect.

## Additions with no use here

The release also adds the following, and no code in the workspace fits them:

- `bool::toggle`. No code negates a `bool` in place.
- `Box::map`, `Rc::map`, `Arc::map`, and `Box::take`. Each `Arc::new` in the workspace builds a fresh
  value rather than mapping an existing one.
- `core::mem::DropGuard`. The workspace has no `Drop` impl and no hand-written cleanup.
- The allocator API, from `Allocator` to `Vec::new_in`.
- `impl PartialEq<Cow<'_, [U]>>` for vectors and slices, and `impl Default for Once`. The workspace
  uses neither `Cow` nor `Once`.
- `extern "custom"`, `-Cprofile-sample-use`, and the additions for Windows.

Cargo also moves intermediate build artefacts to a new layout. No recipe or script reads them, so
nothing changes.

## For the slice

### Changes to the plan

- **The `TryFrom` decision and task.** The planned impls draw `infallible_try_from` warnings, and
  `From` gives the same guarantee without them. [The never type](#the-never-type) sets out the case.
  The task names `MotisPolylineId`, and the type is `PolylineId`.
- **The esp upgrade task.** If the upgrade fails, the task keeps `!` out of the shared crates. The
  library additions need the same limit, and a `rust-version` of `"1.98"` lets Clippy enforce it, as
  [Toolchains](#toolchains) describes.
- **The wrap-up.** `just clippy` prints Cargo's warnings beside Clippy's. The wrap-up's two tasks
  cover Clippy's lints alone.
- **Consequences elsewhere.** `.claude/memory/working-with-claude.md` says the workspace keeps some
  unused `[workspace.dependencies]` entries on purpose, and restores any that `cargo remove` prunes.
  6a8e701c removes them, and `unused_workspace_dependencies` flags any entry that comes back.

### Opportunities in existing code

- `str::trim_prefix` in place of `strip_prefix` and `unwrap_or`, at
  `crates/predictor/src/sentence.rs:47`, after the esp upgrade.
- `Path::trim_prefix` in place of `strip_prefix` and an unwrap, at `crates/medallion/src/path.rs:523`
  and `crates/recorder/tests/sessionise.rs:120`.
- `Vec::from_fn` in place of a mapped range, at the eleven sites listed under `Vec::from_fn`.
- A seven-day dependency cooldown in `apps/lookout/.cargo/config.toml`, lifted for
  `just audit-update`.
- The `prerequisites` recipe without its six `--locked` options.
